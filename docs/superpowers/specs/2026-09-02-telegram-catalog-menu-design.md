# תפריט קטלוג ולידים בבוט הלקוחות (טלגרם) — עיצוב

תאריך: 2026-09-02. סטטוס: ממתין לאישור. תלוי בספק "משימות כתור פעולות אנושיות" (יצירת משימה לליד).

## מטרה

לקוח בבוט הלקוחות (`@aielec_support_bot`, WF5) יכול לדפדף בקטלוג בכפתורים במקום להקליד: קטגוריה → מוצר → מפרט → "מעוניין". לחיצה על "מעוניין" יוצרת ליד ב-Airtable, מבקשת טלפון בלחיצה אחת, ומודיעה לבעל העסק. הצ'אט החופשי עם סוכן ה-AI ממשיך לעבוד במקביל.

## ניתוב ב-WF5 (בוט)

הטריגר מאזין ל-`message` ול-`callback_query`. צומת Switch מיד אחריו מנתב לפי סדר:

| תנאי | מסלול |
|---|---|
| קיים `callback_query` | תפריט |
| קיים `message.contact` | חיבור טלפון לליד |
| `message.text` הוא `/start` או `/menu` | תפריט (מסך הבית, הודעה חדשה) |
| `message.text` הוא `דלג` | הסרת מקלדת + מסך הבית |
| אחרת | הסוכן הקיים (Support Core), ללא שינוי |

כל לחיצת כפתור מקבלת `answerCallbackQuery` כדי לעצור את הספינר, ואז `editMessageText` על אותה הודעה. הצ'אט לא מתמלא בהודעות.

## מצב ללא state

כל המידע הדרוש נמצא ב-`callback_data` (מגבלת טלגרם: 64 בתים):

| callback_data | מסך |
|---|---|
| `home` | בית |
| `cat:{שם קטגוריה}` | רשימת מוצרים בקטגוריה |
| `p:{SKU}` | מפרט מוצר |
| `lead:{SKU}` | יצירת ליד |

שמות הקטגוריות בעברית תופסים 2 בתים לתו, כלומר עד 30 תווים. הקטגוריות הקיימות קצרות. אם תתווסף קטגוריה ארוכה, הצומת חותך ל-30 תווים ומשווה עם `startsWith`.

## מסכים

הנתונים מגיעים מטבלת `Products` (search, כל הרשומות; הקטלוג קטן). צומת Code אחד (`Render Menu`) מקבל את הרשומות ואת ה-`callback_data` ומחזיר `{text, keyboard}`.

1. **בית.** טקסט: "במה תרצו להתעניין?". כפתור לכל קטגוריה ייחודית (ממוינות לפי א"ב), אחד בשורה, ולבסוף "שאלה חופשית" (`callback_data=ask`, מחזיר הסבר קצר: "כתבו כאן כל שאלה").
2. **קטגוריה.** טקסט: שם הקטגוריה. כפתור למוצר: `{שם} · {מחיר} ₪`, אחד בשורה, עד 10. מוצרים ללא מלאי מופיעים עם "(אזל)". שורה אחרונה: "חזרה".
3. **מוצר.** טקסט (HTML):
   ```
   <b>{שם}</b>
   {מק"ט} · {מחיר} ₪
   • {Highlight 1}
   • {Highlight 2}
   • {Highlight 3}
   {במלאי | אזל מהמלאי | שירות — זמין תמיד}
   ```
   כפתורים: "מעוניין", ואז שורה של "חזרה לקטגוריה" + "תפריט ראשי".
4. **מעוניין.** ראו "יצירת ליד". ההודעה מתחלפת ל-"מעולה, רשמנו שאתם מתעניינים ב-{שם}." ומגיעה הודעה חדשה עם מקלדת תגובה: כפתור "שתף טלפון" (`request_contact`) וכפתור "דלג". `one_time_keyboard=true`.

## יצירת ליד

לחיצה על `lead:{SKU}`:

1. חיפוש ליד קיים: `AND({TelegramChatId}='{chat id}', {Status}='New', FIND('{SKU}', {Note}))`. אם קיים, לא יוצרים שוב, רק ממשיכים לבקשת טלפון.
2. אחרת `create` ב-`Leads`:
   - `Name`: `first_name last_name` מטלגרם (או `username` אם אין שם).
   - `Status`: `New`.
   - `Source`: `telegram`.
   - `Note`: `מתעניין ב{שם מוצר} ({SKU})`.
   - `TelegramChatId`: `chat.id` כטקסט.
   - `Email`, `Company`: ריקים.
3. יצירת משימה: `לחזור ל{שם} — {מוצר}`, `Source=lead`, `RefId=record id`.
4. הודעה לבעל העסק דרך בוט המנהל (`OWNER_CHAT_ID`): `📞 ליד חדש מטלגרם\n{שם} · {מוצר} {SKU}\nטלפון: יתעדכן אם ישותף`.

**חיבור טלפון.** כשמגיעה הודעת `contact`: חיפוש `{TelegramChatId}='{chat id}'` ממוין לפי `Created` יורד, הרשומה הראשונה מתעדכנת: `Phone` = מספר הטלפון; אם `Name` ריק, מתמלא משם איש הקשר. תשובה: "תודה {שם}, נחזור אליכם בקרוב." עם `remove_keyboard`, ומיד אחריה מסך הבית. הודעה שנייה לבעל העסק: `טלפון לליד {שם}: {מספר}`.

**דלג.** הסרת המקלדת ומסך הבית. הליד נשאר בלי טלפון; בעל העסק יכול לכתוב ללקוח בטלגרם רק אם יש `username`, ולכן ההודעה לבעל העסק כוללת `@username` כשקיים.

## סכימת Airtable — Leads

| שדה | סוג |
|---|---|
| Phone | Phone number |
| Source | Single line text: `manual` / `telegram` |
| Note | Long text |
| TelegramChatId | Single line text |

`airtable/add-fields.sh`, `schema.md`, `verify-schema.sh` מתעדכנים. לידים שנוצרים מהאפליקציה מקבלים `Source=manual`.

## השלכות על workflows קיימים

- **WF2 (כפילויות).** היום מזהה לפי `Email` בלבד; ליד בלי אימייל היה מסומן כפול של כל ליד אחר בלי אימייל. השינוי: אם יש `Email` — כפילות לפי אימייל; אחרת אם יש `Phone` — לפי טלפון; אחרת `New` בלי בדיקה. לידים מטלגרם נוצרים בלי טלפון ולכן תמיד `New`; הטלפון מגיע אחר כך ולא מפעיל את הטריגר (הטריגר על `Created`).
- **WF3 (מייל קר).** הפילטר הקיים `AND({Status}='New', {Email}!='')` כבר מדלג על לידים בלי אימייל. אין שינוי.
- **WF5-core (סוכן AI).** אין שינוי. הפרומפט מקבל משפט אחד: "אם הלקוח רוצה שיחזרו אליו, הפנה אותו ל-/menu ולכפתור 'מעוניין'". בלי כלי חדש לסוכן (YAGNI; התפריט מכסה את זה).

## שינויים באפליקציה

- `LeadFields` מקבל `Phone?`, `Source?`, `Note?`, `TelegramChatId?`.
- מסך הלידים מציג טלפון (מונו, `dir=ltr`) ותג מקור; ה-Note מופיע בשורה משנית.
- טופס "ליד חדש" מקבל שדה טלפון אופציונלי; `parseLeadForm` מאמת פורמט ישראלי כמו ב-WF10.

## טיפול בשגיאות

- כשל Airtable בתפריט: `editMessageText` עם "משהו השתבש, נסו שוב" וכפתור "תפריט ראשי". השגיאה מגיעה ל-WF-Error.
- `callback_data` לא מוכר (למשל SKU שנמחק): מסך הבית עם "המוצר כבר לא זמין".
- `callback_query` ישן מהודעה שכבר נערכה: `editMessageText` יחזיר "message is not modified"; הצומת מסומן `continueOnFail` והתוצאה מתעלמת.
- לחיצה כפולה על "מעוניין": חיפוש הליד הקיים (סעיף 1 ביצירת ליד) מונע כפילות.

## בדיקות

- **n8n**: `validate_workflow` ו-`get_workflow_details` על WF5 ו-WF2. `test_workflow` עם pin data של `callback_query` לכל מסך (בית, קטגוריה, מוצר, ליד) ושל הודעת `contact`.
- **Vitest** באפליקציה: `parseLeadForm` מקבל ודוחה טלפונים; `statusMeta('Leads', ...)` מציג מקור.
- **קצה לקצה ידני**: `/start` בטלגרם → קטגוריה → מוצר → מעוניין → שתף טלפון. אימות: רשומת Leads עם טלפון, משימה פתוחה, שתי הודעות אצל בעל העסק, WF2 סימן `New`. טקסט חופשי עדיין מגיע לסוכן.
