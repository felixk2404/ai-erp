# AI-ERP — תוכנית 2: n8n workflows

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 12 workflows ב-n8n (9 של המסמך + WF13 + WF9-core + WF-Error), כל אחד כקובץ JSON בריפו שמיובא ומופעל דרך n8n Public API, ונבדק מקצה לקצה עם רשומה/הודעה אמיתית.

**Architecture:** קבצי `n8n/workflows/*.json` הם תבניות עם placeholders (`__AIRTABLE_BASE_ID__`, `__CRED_AIRTABLE__`, `__PROMPT_MANAGER__` וכו'). `n8n/scripts/import-workflow.sh` ממלא אותם מ-`n8n/config.json` (מזהים לא סודיים) ומ-`.env`, יוצר או מעדכן את ה-workflow לפי שם, ומפעיל. הנחיות הסוכנים ב-`n8n/prompts/*.md` ומוזרקות בזמן ייבוא — מקור אחד. סוכן המנהל חי ב-workflow אחד (WF9-core) שנקרא גם מטלגרם (WF9) וגם מהאפליקציה (WF13).

**Tech Stack:** n8n 2.36.9 (Docker), n8n Public API v1, Airtable API, OpenAI (`gpt-5.4-mini`, `text-embedding-3-small`), Supabase pgvector, Gotenberg 8, Telegram Bot API, Gmail/Drive OAuth2, bash + jq + curl.

**Spec:** `docs/superpowers/specs/2026-09-02-ai-erp-design.md`

## Global Constraints

- שמות credentials בדיוק כמו ב-runbook: `Airtable ERP`, `OpenAI ERP`, `Telegram Manager`, `Telegram Customer`, `Supabase ERP`, `ERP Webhook Secret`, `Gmail ERP`, `Google Drive ERP`.
- שמות שדות Airtable בדיוק לפי `airtable/schema.md`. פלט Airtable Trigger: `$json.fields.X`; פלט Airtable search/get: `$json.X` (שטוח) + `$json.id`.
- סטטוסים: Invoices `new → validated → generated → paid` או `error`. Leads (לפי playbook הקורס): `New → Contacted → Qualified` או `Dead` / `Duplicate`. Tasks `open` / `done`.
- מע"מ 18% (17% לפני 2025-01-01). מספור `INV-0001`.
- כל workflow: `settings.executionOrder = "v1"`, `settings.errorWorkflow = <WF-Error id>`.
- מודל: `gpt-5.4-mini` (אותו מודל כמו במרצה). Embeddings: `text-embedding-3-small` (1536).
- טלגרם: `parse_mode` HTML + escape של `& < >` בטקסט מהסוכן. הסוכנים מונחים לא להשתמש ב-Markdown.
- סודות: לעולם לא בקבצי JSON. רק placeholders. סקריפטים טוענים `scripts/load-env.sh`.
- הוק secret-guard: אין `.env` במחרוזת פקודה. קבצים שמזכירים `.env` נכתבים ב-Write tool.
- אחרי כל workflow שעובד: `n8n/scripts/export-workflows.sh` ו-commit.

- [ ] **Step 4: import-workflow.sh**

```bash
#!/usr/bin/env bash
# import-workflow.sh n8n/workflows/NN-name.json [--activate]
# ממלא placeholders מ-config.json, prompts/ ו-.env, יוצר או מעדכן לפי שם, שומר id ב-config.json.
set -euo pipefail
cd "$(dirname "$0")/.." && source scripts/load-env.sh
TPL=$1; ACTIVATE=${2:-}
API=./scripts/n8n-api.sh

# 1. substitutions: config keys, workflow ids, prompts, env
JQ_ARGS=(--rawfile tpl "$TPL" --slurpfile cfg config.json --arg supa "$SUPABASE_URL")
FILTER='$tpl'
for k in $(jq -r 'to_entries[] | select(.value|type=="string") | .key' config.json); do
  FILTER="$FILTER | gsub(\"__${k}__\"; \$cfg[0][\"$k\"])"
done
for k in $(jq -r '.workflows | keys[]' config.json); do
  FILTER="$FILTER | gsub(\"__WF_${k}_ID__\"; \$cfg[0].workflows[\"$k\"])"
done
for p in prompts/*.md; do
  name=$(basename "$p" .md | tr 'a-z-' 'A-Z_')
  JQ_ARGS+=(--rawfile "p_$name" "$p")
  FILTER="$FILTER | gsub(\"__PROMPT_${name}__\"; (\$p_$name | rtrimstr(\"\\n\") | tojson | .[1:-1]))"
done
FILTER="$FILTER | gsub(\"__SUPABASE_URL__\"; \$supa)"
# 2. parse, add node ids, keep only allowed fields
BODY=$(jq -n "${JQ_ARGS[@]}" "$FILTER | fromjson
  | .nodes |= (to_entries | map(.value.id = (.value.id // (\"00000000-0000-4000-8000-\" + ((\"000000000000\" + (.key|tostring))[-12:]))) | .value))
  | {name, nodes, connections, settings: (.settings // {executionOrder: \"v1\"})}")
NAME=$(echo "$BODY" | jq -r .name)
if echo "$BODY" | grep -q '__[A-Z_]*__'; then echo "placeholder לא מולא:"; echo "$BODY" | grep -o '__[A-Z_]*__' | sort -u; exit 1; fi

# 3. create or update
ID=$($API GET "/workflows?limit=250" | jq -r --arg n "$NAME" '.data[] | select(.name==$n) | .id' | head -1)
if [ -n "$ID" ]; then
  RES=$($API PUT "/workflows/$ID" "$BODY")
else
  RES=$($API POST "/workflows" "$BODY")
  ID=$(echo "$RES" | jq -r .id)
fi
[ "$ID" = "null" ] || [ -z "$ID" ] && { echo "$RES" | jq -c '{message, description}'; exit 1; }
# 4. remember id under a key derived from file name: 00-error.json -> ERROR, 09b-manager-core.json -> MANAGER_CORE
KEY=$(basename "$TPL" .json | sed -E 's/^[0-9a-z]+-//' | tr 'a-z-' 'A-Z_')
jq --arg k "$KEY" --arg id "$ID" '.workflows[$k] = $id' config.json > config.json.tmp && mv config.json.tmp config.json
ACTIVE=false
if [ "$ACTIVATE" = "--activate" ]; then ACTIVE=$($API POST "/workflows/$ID/activate" | jq -r '.active // .message'); fi
echo "$NAME  id=$ID  active=$ACTIVE"
```

- [ ] **Step 5: export-workflows.sh + executions.sh**

```bash
#!/usr/bin/env bash
# export-workflows.sh — מושך את כל ה-workflows ל-n8n/workflows/exported/<name>.json (מקור האמת להגשה)
set -euo pipefail
cd "$(dirname "$0")/.." && source scripts/load-env.sh
mkdir -p workflows/exported
./scripts/n8n-api.sh GET "/workflows?limit=250" | jq -c '.data[]' | while read -r wf; do
  id=$(echo "$wf" | jq -r .id); name=$(echo "$wf" | jq -r .name | tr ' /' '__')
  ./scripts/n8n-api.sh GET "/workflows/$id" | jq '{name, nodes, connections, settings, active}' > "workflows/exported/$name.json"
  echo "exported $name"
done
```
