# Craft contract — every storefront UI task (binding)

You are building for a portfolio at the level of a 40-year web design lead. "Correct" is not enough; it must look *decided*. Before writing each component, state (in your report) Intent / Hierarchy / Palette / Depth / Typography / Spacing for it, then build.

## Design system (spec §7, `store/.interface-design/system.md`)
- Surfaces: `bg-void` page, `bg-panel-1/2/3` stepping up only +3–4 % lightness each; borders `border-rule` (rgba .08) / `border-rule-strong` (.16); depth = borders + one radial `beam-soft` glow behind the focal object. No drop shadows on dark.
- Text ramp: `text-glow` (primary) / `text-glow-2` (secondary) / `text-glow-3` (meta) / `text-glow-4` (disabled). Never gray-500 style hardcodes.
- Accent `beam` ≤ 10 % of any screen: primary button, active pill, focus ring, stock dot, free-shipping bar. Status: `ok` / `warn` / `bad` only for status.
- Type: Heebo 800 for display (44–96 px, tracking −0.02em, `text-wrap: balance`), Heebo 500 for labels, 400 for body 16/1.5; JetBrains Mono `.num` for every price, SKU, quantity, spec value (`tabular-nums`). Scale: 11 / 14 / 16 / 18 / 22 / 28 / 44 / 64 / 96.
- Grid 8 px. Container 1280. Card padding 16. Section gaps 96 desktop / 64 mobile. Radius 8 (inputs/buttons) / 12 (cards) / 16 (sheets, modals).
- One focal point per screen (hero product / the product image / the checkout CTA / the order number). Demote everything else on purpose.
- Uneven rhythm: dense control rows, generous air between sections. Never a monotone grid of identical boxes without a lead.

## Motion (spec §7; motion-react skill)
- `motion/react` (`motion/react-client` in server files). `MotionConfig reducedMotion="user"` is global; additionally gate transform-heavy effects (tilt, fly, float, blur) with `useReducedMotion()`.
- Springs: `{ type: 'spring', bounce: 0.15–0.3, visualDuration: 0.25–0.4 }`. UI feedback < 300 ms. Exits shorter than entrances. Only `transform`, `opacity`, `filter`, `clip-path` animate. No `transition: all`.
- Every animation answers "what does this communicate?" (arrival, continuity, causality). No decoration loops except the hero float (6 s) and the support pulse (every 8 s).
- Shared element: product image `Shared name={`product-image-${sku}`}` card → product page; directional page transitions `nav-forward`/`nav-back` on Links.

## RTL and a11y
- `dir="rtl"` root; only logical utilities (`ps- pe- ms- me- start- end- text-start text-end`). Mono/LTR fragments (SKU, email, phone) get `dir="ltr"` on an inline element, never on the cell/container.
- Keyboard: every control focusable, `focus-visible` ring `beam`, hit area ≥ 40 px, `aria-label` on icon buttons, form errors via `aria-describedby`, `aria-live` for cart/chat updates.
- Images: `next/image` with `sizes`, `alt` = product name; hero `priority`.

## States and copy
- Every list/section: loading (skeleton with the same dimensions), empty (one sentence + one action), error (one sentence + retry).
- Hebrew microcopy: short, active, no emoji, no exclamation spam. Prices always `ils()`. Stock: only "במלאי" / "אזל" — never a number.
- No `console.log`, no unused code, no `any`, no inline `style` except motion values.
