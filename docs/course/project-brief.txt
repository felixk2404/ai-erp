1. מה זה בכלל הפרויקט הזה?
זהו פרויקט ללימוד — מערכת ERP קטנה עבור עסק אלקטרוניקה ישראלי דמיוני. ERP (ראשי תיבות של Enterprise Resource Planning) הוא פשוט "מערכת שמנהלת את כל העסק במקום אחד": לקוחות, הזמנות, חשבוניות, מלאי, ספקים, עובדים וכסף.
מה שמיוחד כאן: במקום שאדם יעשה הכל ידנית, סוכני בינה מלאכותית ותהליכים אוטומטיים עושים חלק גדול מהעבודה — עונים ללקוחות, שולחים מיילים, מפיקים מסמכי חשבונית, ומנתחים את העסק. מעל הכל יושבת אפליקציה שנבנית ב-Lovable או ב-Base44, ודרכה בעל העסק רואה ומנהל את הנתונים.
אפשר להריץ את כל המערכת בנוחות על n8n Cloud — בלי להתקין שרתים משלך — ואת האפליקציה על הענן של Lovable או Base44.
2. המושגים הבסיסיים — בשפה פשוטה
מושג
	מה זה, בפשטות
	n8n
	כלי "אוטומציה בגרירה". בונים שרשרת של פעולות ("כשקורה X — תעשה Y ואז Z") בלי לכתוב הרבה קוד. הלב של המערכת.
	Workflow
	תהליך אחד ב-n8n. למשל: "כשנוצרת חשבונית — בדוק אותה, צור מסמך, שמור בדרייב".
	סוכן AI (Agent)
	מודל שפה שמקבל הוראה + כלים (חיפוש, שליחת מייל) ומחליט בעצמו מה לעשות כדי לענות.
	RAG
	"חיפוש לפני תשובה". הסוכן שולף קטעים רלוונטיים מתוך מסמכי העסק ורק אז עונה — כך הוא לא ממציא.
	Airtable
	מסד נתונים שנראה כמו גיליון אקסל יפה בענן. זהו בסיס הנתונים היחיד של הפרויקט.
	Embeddings
	המרה של טקסט למספרים (וקטור), כדי שאפשר יהיה למצוא טקסטים "דומים במשמעות".
	צומת (Node)
	קופסה אחת בתהליך שעושה דבר אחד: קוראת מ-Airtable, שולחת מייל, מסכמת מספרים. גוררים אותה מהתפריט ומחברים — לא כותבים אותה.
	Lovable / Base44
	פלטפורמות שבונות אפליקציית ווב מתוך תיאור בשפה חופשית. כאן הן משמשות לממשק הניהול של המערכת.

5. סוכני ה-AI — שלושת העובדים הדיגיטליים
סוכן המנהל (Manager)
לבעלים בלבד, דרך בוט טלגרם. עונה על שאלות אנליטיקה: הכנסות, מספר חשבוניות, וסכומים שלא שולמו.
הנתונים מחושבים לפניו בצמתים מוכנים (Summarize), ולסוכן נשאר רק לנסח את התשובה בעברית — כך אין מה לנפות בקוד. דוגמה: "מה ההכנסות?"
סוכן שירות לקוחות (Customer Service)
ללקוחות, דרך בוט טלגרם שני. עונה על שאלות ומעוגן ב-RAG (לא ממציא — שולף ממדיניות העסק).
דוגמאות: "מה מדיניות ההחזרות?" · "יש לכם אוזניות אלחוטיות?"
סוכן מכירות (Sales)
שולח מיילים קרים ללידים, ומדי חצי שעה בודק אם הגיעו תשובות ומעדכן את סטטוס הליד.
רץ ברקע לפי לוח זמנים — בלי התערבות אנושית.
6. RAG — איך הסוכן "יודע" את המדיניות
במקום לסמוך על הזיכרון של המודל, RAG עובד בשלושה שלבים פשוטים:
15. הכנה (פעם אחת): עמוד המדיניות וקטלוג המוצרים עוברים המרה ל-embeddings ונשמרים במאגר וקטורי.
16. שליפה: כשלקוח שואל שאלה, השאלה עצמה הופכת לוקטור, והמערכת מוצאת את הקטעים הכי דומים במשמעות.
17. תשובה: הקטעים שנמצאו נדחפים לתוך ההנחיה של הסוכן, והוא עונה מבוסס עליהם בלבד.
המדיניות היא בעברית ויושבת בתוך WF6, בצומת "עריכת שדות". הוא מכסה: שעות פעילות, משלוחים, החזרות והחלפות, אחריות, תשלומים ומחירים, מסמכי מס, סטטוסים של הזמנה, גבולות לסוכן, וטון שיחה.
אין קובץ ואין תיקייה. רוצים לשנות את המדיניות? פותחים את הצומת בדפדפן, לוחצים על תיבת הטקסט ועורכים. אחרי כל שינוי מריצים את WF6 מחדש.

נקודת פתיחה לפרומפט הבנייה
Build an internal admin app for a small Israeli electronics business.
Hebrew UI, RTL layout, ILS currency, dd/mm/yyyy dates.
Screens: Dashboard, Customers, Leads, Orders, Invoices, Products, Tasks.
Data comes from a REST endpoint I will provide (n8n webhook) - do not
create your own database. All writes POST to the same webhook with a
JSON body: { action, table, payload }.
Add a chat panel that POSTs { action: "chat", message } and renders
the "reply" field from the response.
אחרי הפרומפט הראשוני ממשיכים בשיפורים קטנים ("הוסף סינון לפי סטטוס", "הפוך את הדשבורד לשתי עמודות") — כך עובדים בפלטפורמות האלה.
9. הנתונים — הסכימה כמקור האמת

10. מסמכי מס וחוקי המע"מ בישראל
המערכת מיישמת כללי מס ישראליים בסיסיים:
* מע"מ 18% (17% לפני 01/01/2025).
* מספור מסמכים רץ — כל מסמך מקבל מספר עוקב.
* הבחנה בין סוגי מסמכים: חשבונית מס, קבלה, וחשבונית.
תבנית החשבונית היא HTML בעברית RTL שיושב בתוך WF8, בצומת "בניית HTML". התהליך ממלא אותה בנתוני החשבונית, הופך אותה לקובץ, ומעלה לגוגל דרייב. האפליקציה רק מציגה את הקישור.
ואיפה ה-PDF? הפרויקט לא משתמש בשירות המרה חיצוני — כדי שלא יהיה שרת להקים. מי שרוצה PDF: בדרייב, לחיצה ימנית על הקובץ ← פתיחה באמצעות Google Docs ← File ← Download ← PDF.
מגבלה: מספור רץ עלול "להתנגש" אם שני מסמכים נוצרים באותו חלון סקירה (poll).

12. איך מריצים — צעד אחר צעד
0. פותחים חשבונות
n8n Cloud, Airtable, OpenAI, שני בוטי טלגרם מ-BotFather (אחד למנהל ואחד ללקוחות), וחשבון גוגל ל-Gmail ולדרייב. זה כל מה שצריך — אין תוכנה להתקין.
1. מחברים את החשבונות ל-n8n
ב-n8n: Credentials ← Add credential. שישה חיבורים: Airtable, OpenAI, טלגרם (מנהל), טלגרם (לקוחות), Gmail, ו-Google Drive.
2. בונים את הבסיס ב-Airtable
יוצרים את ארבע הטבלאות מסעיף 9 עם השדות בדיוק כמו שם. הבסיס מתחיל ריק — את הרשומות מוסיפים תוך כדי העבודה. יש מדריך נפרד ומפורט לשלב הזה, כולל הפקת Access Token.
3. מכניסים את התהליכים ל-n8n

13. מגבלות מוכרות (בכוונה, לשם הפשטות)
* המאגר הווקטורי וזיכרון הסוכנים יושבים בזיכרון — ונמחקים בכל הפעלה מחדש של n8n. הריצו שוב WF6 + WF7.
* אין המרה ל-PDF. החשבונית נשמרת כמסמך HTML בדרייב, וההמרה ל-PDF היא לחיצה אחת ידנית — כך נמנעים משירות חיצוני שצריך להקים.
* טריגרים של Airtable סורקים כל דקה לפחות, ומסתמכים על שדה Created time.
* מספור חשבוניות רץ עלול להתנגש אם שתי חשבוניות נוצרות באותה דקה.
* Google OAuth במצב "Testing" — טוקן הרענון פג אחרי 7 ימים.
* אין טיפול בשגיאות ואין ניסיונות חוזרים: כשמשהו נכשל רואים אותו אדום ב-Executions. זה מכוון — כך לומדים לקרוא הרצות.
* סוכן המנהל לא מקבל כלים ולא יוצר משימות בעצמו (זה תרגיל להמשך), והוא רואה עד 100 חשבוניות.
* WF4a שולח ליד אחד בכל הרצה, כדי שטעות לא תשלח עשרות מיילים.
* קשרים בין טבלאות הם מפתחות זרים כטקסט, לא קישורי Airtable.
* האפליקציה: משתמש אחד בלבד, בלי הרשאות ובלי מטמון; מכסת ה-API של Airtable (כ-5 בקשות לשנייה) מגבילה דשבורדים כבדים.
* נעילת פלטפורמה: מה שנבנה ב-Lovable אינו זהה למה שנבנה ב-Base44. הטבלאות וה-webhook הם החלק הנייד — הממשק לא.
14. מילון מונחים מהיר
מונח
	הסבר
	ERP
	מערכת לניהול כל משאבי העסק במקום אחד.
	Webhook
	כתובת שמקבלת "דחיפה" של אירוע ומפעילה תהליך.
	Poll / סריקה
	בדיקה חוזרת בפרקי זמן ("יש משהו חדש?").
	Vector store
	מאגר שמאחסן embeddings ומאפשר חיפוש לפי דמיון משמעות.
	Lead / ליד
	לקוח פוטנציאלי שעדיין לא קנה.
	OAuth
	דרך מאובטחת לתת לאפליקציה גישה לחשבון (גוגל) בלי סיסמה.
	REST API
	ממשק שמאפשר לתוכנות לדבר זו עם זו דרך HTTP.
	Lovable
	פלטפורמה שבונה אפליקציית ווב מתוך תיאור בצ'אט, עם פונקציות שרת לסודות.
	Base44
	פלטפורמת בניית אפליקציות בשפה חופשית, עם אינטגרציות מוכנות ו-secrets מנוהלים.
	Secret
	מפתח או כתובת רגישה שנשמרת בצד השרת ולא נחשפת בדפדפן.
	צומת (Node)
	קופסה בתהליך שעושה דבר אחד. גוררים מהתפריט ומחברים.
	Summarize
	צומת שמסכם, סופר או מחשב ממוצע על כל השורות שנכנסו אליו — בלי קוד.
