## 1. מה נמצא (חקירה לפני תיקון)

### הבאג שדווח
`08-invoice-pdf.json` · `Build HTML` הציג שורות במחיר **כולל** מע"מ, ומיד מתחתיהן `סה"כ לפני מע"מ = Amount = Total/1.18`.
סכום השורות היה **גדול** מהמספר שמתחתיו, המשלוח לא הופיע בכלל, ולא היה גילוי נאות של הדגמה.

### שורש הבעיה — עמוק יותר מהדיווח
לטבלת `Invoices` יש **שני יצרנים עם שתי מוסכמות סותרות** לאותם שדות:

| | `Items` | `Amount` | `Total` | האם השורות מסתכמות ל-Total? |
|---|---|---|---|---|
| **WF10** (הזמנה מהחנות) | מחירי קטלוג כולל מע"מ, **בלי משלוח** | `Total/1.18` | `subtotal + shipping` | ✗ (חסר המשלוח) |
| **האפליקציה** (`invoices/parse.ts` → WF1) | אותם מחירי קטלוג כולל מע"מ | `sumItems(items)` | `Amount × 1.18` (ב-WF1 `Compute`) | ✗ (Total גדול ב-18%) |

כלומר האפליקציה מחשבת **מע"מ על מחיר שכבר כולל מע"מ** — מוצר של 1,000 ₪ בחנות הופך ל-1,180 ₪ בחשבונית ידנית.
לכן שום עיצוב של ה-PDF לבדו לא יכול היה להסתדר: כל בחירה נכונה למסלול אחד שוברת את השני. חייבים לאחד את המוסכמה אצל היצרן.

**המקור לאמת:** `store/src/content/policies.ts:52` — "כל המחירים המוצגים כוללים מע״מ", ו-`store/src/lib/cart.ts:23` — `vat = total − total/1.18`. החנות, הסל, מייל האישור ו-WF10 כולם במוסכמה של מחיר כולל מע"מ. **האפליקציה היא החריגה.**

## 2. ההחלטה — אפשרות (ב)

**נבחרה (ב): להשאיר את המחירים כולל מע"מ ולהתאים את בלוק הסיכום.**

למה, על סמך הראיות:

1. **זה הדיף הקטן ביותר.** אפשרות (א) — להציג הכל לפני מע"מ — הייתה מחייבת לחלק כל שורה ב-1.18 ב-PDF, וגם את שורת המשלוח, ולהמציא מספרים ששום מסך אחר במערכת לא מציג. אפשרות (ב) לא נוגעת באף מחיר.
2. **היא שומרת על מוסכמה אחת בכל המערכת.** החנות, הסל, מייל האישור, הודעת הטלגרם ועמוד המעקב כולם כבר מציגים מחיר כולל מע"מ. (א) הייתה יוצרת מסמך יחיד שמדבר בשפת מספרים אחרת מכל השאר.
3. **היא נכונה מבחינת מסמך מס ישראלי.** המסמך מציג את הסכום לתשלום, את המע"מ הגלום בו ואת הסכום לפני מע"מ — שלושתם, ושלושתם מסתדרים.
4. **הטור נסגר במקום שהעין מגיעה אליו.** `סה״כ לתשלום` יושב מיד אחרי השורות, עם הקו העבה מעליו. מי שיסכם את הטור יקבל בדיוק את המספר הזה.

**האינווריאנט שנקבע:** `Total = סכום שורות ה-Items` (כולל שורת משלוח מפורשת) · `Amount + VatAmount = Total`.

## 3. מה שונה

### `n8n/workflows/10-order.json` · `Compute`
המשלוח נכנס כשורה מפורשת ב-`Items` של **החשבונית** בלבד (להזמנה יש שדה `Shipping` משלה, היא לא נגעה):

```js
const invoiceItemsJson = JSON.stringify(shipping
  ? [...items, { sku: 'SHIPPING', name: 'משלוח', qty: 1, price: shipping }]
  : items);
...
invoiceFields: { ..., Items: invoiceItemsJson, ... }
```

לא נוסף שדה חדש ב-Airtable — כך שהאפליקציה, ה-PDF וכל צרכן עתידי רואים את המשלוח מאותו מקום.

### `n8n/workflows/08-invoice-pdf.json` · `Build HTML`
- כותרת העמודה `מחיר` ← `מחיר כולל מע״מ`
- בלוק הסיכום התהפך: `סה״כ לתשלום` (Total, סוגר את הטור) → `מתוכו מע״מ 18%` (VatAmount) → `סה״כ לפני מע״מ` (Amount)
- `.foot`: נוסף גילוי נאות בניסוח **המדויק של מייל האישור** — `זו הדגמה — לא בוצע חיוב.` (מודגש), והוסר `כחוק` שחיזק את הרושם שזו חשבונית אמיתית

### `app/src` (מינימלי — נדרש כדי שהמוסכמה תהיה אחת)
- `lib/invoice-items.ts`: נוסף `vatOf(total)` — חילוץ מע"מ מסכום שכולל אותו
- `invoices/parse.ts`: `Amount` כבר לא סכום השורות אלא `Total − VatAmount`; הפונקציה כותבת גם `VatAmount` ו-`Total` במפורש, כך ש-WF1 מעביר אותם כמו שהם (ה-`||` שלו) ואין סחיפת עיגול של אגורה
- `invoices/new-invoice-dialog.tsx`: התצוגה בטופס מראה עכשיו את אותם מספרים שהשרת יכתוב (קודם הבטיחה 1,180 ומה שנוצר היה 1,000)
- `invoices/parse.test.ts`: הבדיקה מאשרת את האינווריאנט `Amount + VatAmount = Total`

**לא נגעתי** ב-`invoices/[id]/page.tsx` ובעמוד רשימת החשבוניות — שניהם מציגים `Amount / VatAmount / Total` ונכונים כמו שהם תחת המוסכמה החדשה.
**לא נגעתי** בממצאי הקופי של הסוכן השני (`פירוט` ← `פריט` מ-M-21, וגרשיים ב-`<th>סה"כ</th>`). בטקסטים שכתבתי מחדש השתמשתי בגרשיים עבריים.

## 4. בלוק המספרים — לפני ואחרי

### לפני (הזמנה עם משלוח, לפי הקוד שהיה)

```
כבל USB-C 100W  ×2   45.00 ₪    90.00 ₪
                                          ← המשלוח (29 ₪) לא הופיע בשום מקום
סה"כ לפני מע"מ                 100.85 ₪   ← גדול מסכום השורות (90.00)
מע"מ 18%                        18.15 ₪
סה"כ לתשלום                    119.00 ₪   ← לא נובע משום דבר שמעליו
```
90.00 ≠ 100.85, ו-90.00 ≠ 119.00. **הטור לא מסתדר.**

### אחרי (INV-0012 — ה-PDF שנפתח בפועל)

```
כבל USB-C 100W  ×2   45.00 ₪    90.00 ₪
משלוח SHIPPING  ×1   29.00 ₪    29.00 ₪
────────────────────────────────────────
סה״כ לתשלום                    119.00 ₪
מתוכו מע״מ 18%                  18.15 ₪
סה״כ לפני מע״מ                 100.85 ₪
```
90.00 + 29.00 = **119.00** ✓ · 100.85 + 18.15 = **119.00** ✓

### אחרי (INV-0011 — משלוח חינם, מעל 300 ₪)

```
אוזניות TY-200        ×1   349.00 ₪   349.00 ₪
כבל USB-C 100W        ×2    45.00 ₪    90.00 ₪
──────────────────────────────────────────────
סה״כ לתשלום                            439.00 ₪
מתוכו מע״מ 18%                          66.97 ₪
סה״כ לפני מע״מ                         372.03 ₪
```
349.00 + 90.00 = **439.00** ✓ · 372.03 + 66.97 = **439.00** ✓
